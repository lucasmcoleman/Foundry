### Design decisions (rationale recorded once, here)
- **Interface**: `Environment.generate(task_params, seed) -> Task`,
  `Environment.verify(task, response) -> VerifyResult{reward, diagnostics}`.
  Tasks are frozen dataclasses, JSON-serializable end-to-end so the TRL reward
  adapter can round-trip them through a HF Dataset column.
- **Determinism**: every env draws only from `random.Random` seeded by
  sha256(env, canonical(task_params), seed); no global RNG, no set/dict iteration
  order dependence. Enforced by tests (same seed → byte-identical task JSON).
- **Rewards in [0,1]**, mostly outcome-gated with ≤0.1 format shaping, so GRPO
  group advantages stay meaningful and shaping can't dominate.
- **Five families**:
  1. `code_repair` — AST fault injection into a curated corpus of self-contained
     Python modules; reward = hidden I/O test cases passing in a hardened sandbox.
     (Real-repo fault injection rejected for the v1 loop: per-rollout verify must be
     sub-second on this box; corpus modules are realistic but self-contained.)
  2. `tool_orchestration` — mock MCP-style tool servers over deterministic state
     machines; model emits a JSON plan of tool calls with `$from` data-flow
     references; reward = goal-state predicates after simulation.
  3. `struct_extract` — synthetic documents rendered from known ground truth;
     schema-gated field-level scoring with normalizers.
  4. `math_logic` — arithmetic/number-theory/linear-systems/logic-counting with
     exact reference checkers; `Answer:`-line extraction, strict single-answer parse.
  5. `orchestrator_planning` — **the judgment-call family**: policy writes a
     delegation plan (subtasks → typed workers, dependencies, budget); a
     deterministic simulator executes it; reward = outcome predicates (goal
     artifacts produced with valid provenance) + budget/deadline constraints.
     Chosen because it directly trains orchestrator behavior (decomposition,
     capability matching, dependency ordering, parallelism under worker-serial
     execution) while staying airtight: plans are scored by simulated outcome,
     not by text similarity — no judge model anywhere.
- **Anti-__eq__-spoofing**: all value comparisons in verifiers go through
  `checkers.canonical()` which requires exact builtin types (`type(x) is int` etc.),
  so a candidate returning objects with permissive `__eq__` fails canonicalization.
- **Sandbox** (`core/sandbox.py`): `python -I` subprocess, nonce protocol
  (nonce drained from a pipe before candidate import → candidate cannot forge the
  result line), rlimits (CPU/AS/FSIZE/NOFILE), socket stub, wall-clock kill of the
  process group. Residual risk documented in verifier-audits.md.
